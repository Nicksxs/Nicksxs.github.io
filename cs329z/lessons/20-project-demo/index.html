期末项目｜把 Agent 演示做成可复现的评测

基于 Stanford CS329Z 项目要求整理选题、基线、失败分析与复现检查，适用于自学项目。

2026 年 12 月 9 日 · 项目演示准备，依据官方项目要求编写。 项目说明

定题时同时定验收条件

把题目写成「用 Agent 帮实验室管理设备」太宽。可以把首版边界收在「根据用户给的日期和时间段，判断指定设备能不能预约」。这就能建立一个程序基线。把日期解析好，读取已有预约，再用明确的时间区间规则得出结果。如果 Agent 增加了从口语补齐信息的能力，就用有完整条件和有缺失条件的两类任务比较，看看差异发生在哪一类。 官方项目说明

准备同一批任务给基线和 Agent。记录输入数据版本、运行环境、时间预算与验证规则。同一个配置可以多跑几次，保存每次的结果。答复中的日期、设备号或冲突状态尽量做确定性比对。如果用模型裁判判断解释清晰度，把评分准则和与人工标注的对照写在报告里。 项目说明 · 官方评测课件

从失败案例讲清改动的收益

演示可以按一条成功任务、一条失败任务、一次对照的顺序来讲。失败日志标明最早偏离预期的地方，例如日期解析错、查错设备，或工具超时后答复仍声称查到了。把这条日志放回任务集里，改动后再跑一遍。报告里可以同时给通过率和延迟，再说明哪类样本改善、哪类样本还有问题。隐私字段、写操作与授权要求也属于项目设计的一部分。 官方项目说明

交稿前做一次独立复现

从空目录按 README 安装固定版本的依赖，用示例配置启动项目。按说明跑一条成功样例、一条失败样例，再运行完整评测。预期能找到当时使用的数据版本、输出文件和分数来源。没有 API 凭据时，可以用模拟工具替身检验控制流，把结果与真实模型的结果分别记录。正式提交的报告格式、AI 使用披露、代码仓库和提交时间，以项目说明及官网课表为准。 官方项目说明 · 官方课表
