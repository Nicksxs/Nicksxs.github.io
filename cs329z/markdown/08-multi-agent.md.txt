# 第 8 讲｜多 Agent 的编排、交接与协调

授课日期 2026 年 10 月 19 日

要同时确认相机库存和场地是否开放，可以把两项查询并行处理。如果还要占用同一个时段，就得明确谁能提交预约。多 Agent 设计的收益取决于任务能否拆开，以及不同执行者怎样对齐进度和权限。

## 先找适合并行的工作

在输入可拆、结果可合并时，独立执行再汇总通常就够了。若需要根据中间结果调整分工，可以由中央编排器指派子任务、收回结果。去中心化模式允许成员直接交换消息和自行领任务。混合模式由编排器负责总体进度，在确有依赖的子任务间允许直接协商。分工能让每个成员只看自己的上下文，也增加了工具调用、信息交接和合并的开销。课件根据对比研究建议先跑一个强的单 Agent 基线，再用对齐的预算和工具比较同一组任务。[Stanford 第 8 讲课件](https://web.stanford.edu/class/cs329z/slides/lecture08.pdf) · [Agent 扩展研究](https://arxiv.org/abs/2512.08296)

## 分清交接和共享状态

Handoff 把后续对话控制权交给接手者。把另一个 Agent 作为工具调用时，主 Agent 保留控制权，把限定范围的请求发给它，再汇总返回的结果。比如用户要改约时间，可以由预约 Agent 接管后续对话。只需核对场地开放时间时，场地 Agent 返回时间范围和资料编号即可。通信解决「谁收到哪条消息」，协调还要解决「谁负责哪一步、哪一步在等什么、冲突怎么处理」。A2A 为跨系统的发现和消息交换提供接口，任务归属和写入约束仍须由应用约定。[Stanford 第 8 讲课件](https://web.stanford.edu/class/cs329z/slides/lecture08.pdf)

任务账本可以记目标、负责人、依赖和完成条件。共享记忆保存可复用的协作经验。有文件修改时，可给各成员单独的工作目录，再集成与验证结果。独立工作目录能减少覆盖，集成时仍要处理接口和语义冲突。课件也指出，协作失败往往出在规格、成员间对齐或结果验证上，复盘时可以据此定位。[Stanford 第 8 讲课件](https://web.stanford.edu/class/cs329z/slides/lecture08.pdf) · [多 Agent 失败研究](https://arxiv.org/abs/2503.13657)

## 动手检查失败路径

在纸上写一张任务账本，列出「查设备」「查场地」「提交」三个任务。前两项各有一个负责人，分别回报「设备可借 14:00–16:00」和「场地仅 15:00–17:00 开放」。再模拟两个查询负责人都试图提交。

**预期结果**　主流程给出的共同空档是 15:00–16:00，查询者只读，提交被拦截。只有被授权的提交步骤在用户确认后才能写入一次。用同一组工具结果对比单 Agent 方案，记录决策是否一致以及多出了几次交接。
