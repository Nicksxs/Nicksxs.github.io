# 第 18 讲｜编程 Agent 从定位问题到验证补丁

[课程索引](/cs329z/review/) · <a href="/cs329z/markdown/18-coding-agents.md.txt" download="18-coding-agents.md">下载 Markdown</a>

2026 年 11 月 30 日 · 预习讲义，依据公开课纲和论文编写。 [官方课表](https://cs329z.stanford.edu/)

## 读仓库、改一处、跑一次检查

有人报「导出 CSV 后，最后一行总不见」。编程 Agent 要判断是写出时少了一行，还是读入时漏了一行。它先通过搜索与文件读取定位可能的代码，再用一个可控样例重现行为。读到测试失败后选择修改，查看差异并再次运行测试，才能收集改动有效的证据。这条循环中的观察既包括源码，也包括命令结果、测试失败和编辑器反馈。 [SWE-agent 论文](https://arxiv.org/abs/2405.15793)

## 工具接口会改变 Agent 看到什么

SWE-agent 论文把 Agent 面对计算机的接口当作设计变量。读文件时只返回局部窗口，可以把模型的注意力集中在相关代码。编辑后尽快给语法或测试反馈，便于下一轮调整。窗口太窄时，上游调用条件可能不在视野里。反馈太长时，真正有用的报错容易被淹没。OpenHands 论文则描述了一个把模型、执行环境和不同操作能力接起来的软件开发平台。读这些系统时，可以画出各自的行动接口和观察接口，再回到同一个任务对照。 [SWE-agent 论文](https://arxiv.org/abs/2405.15793) · [OpenHands 论文](https://arxiv.org/abs/2407.16741)

## 把修改与验收分两步写

准备一个本地练习仓库。设导出函数的约定是总写表头并保留各条数据，再故意漏掉最后一条。给它一个输入只有 1 条数据的用例，预期结果有表头和那条数据。另一个用例输入空列表，预期只有表头。让编码 Agent 修复导出逻辑，保存补丁与测试结果。验收时跑两条用例并检查 `git diff`，确认输出和改动范围都符合预期。 [官方评测课件](https://web.stanford.edu/class/cs329z/slides/lecture13.pdf)

扩展对照时，把模型与任务固定，只改工具的输出方式，例如比较整文件与围绕命中行的窗口。记录工具调用数、模型实际接收的文本和测试结果，结论限定在这组任务上。 [SWE-agent 论文](https://arxiv.org/abs/2405.15793)
